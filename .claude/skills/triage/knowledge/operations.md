# Operations — flags, tables, output, labels, composition

Operational reference for `/triage`. Consolidates the former `modes-and-flags.md`,
`proposal-table.md`, `output-format.md`, `label-setup.md`, `composition.md` (Wave-1b
over-fragmentation fix, this cycle).

## Modes and flags (Step 1)

- **Default** — classify, verify, route, order; output proposals, no writes.
- `--repo=<name>` — scope to a specific repo (default: current working repo).
- `--limit=<n>` — cap issues processed (default 100).
- `--filter=<query>` — append a `gh` filter (`is:open label:bug`, etc.).
- `--prs` — include external PRs as a request surface (a PR is an issue with attached
  code; discovery surfaces only *external* PRs — a collaborator's in-flight branch is not
  triage work). An explicitly named PR (`#42`) is always triaged regardless of flags.
- `--apply` — write labels, post comments/briefs, close wontfix via `gh`. Requires user
  confirmation of the proposal table first.
- `--reorder` — output the ordered backlog as a paste-ready checklist, omitting the
  rubric breakdown.

## Proposal table (Step 3)

| # | Title | Severity | Effort | Domain | Type | Route | Reason |
|---|-------|----------|--------|--------|------|-------|--------|
| 12 | Auth bypass on /api/v2/threads | p0 | s | auth | bug | ready-for-agent | data-exposure risk; repro'd; check: `pnpm vitest run threads.auth` |
| 17 | Add markdown preview to chat | p3 | m | ui | feature | ready-for-human | nice-to-have; acceptance is taste-shaped |

The reason column is one short clause citing specifics — the exposure, the repro result,
the check command. "p1 because it's bad" is not auditable; "p0 because data loss" with a
pointer at the actual exposure is. Tag `[PR]` when the `--prs` surface is on.

## Label setup (Step: apply)

Required scheme per repo — severity `severity/p0..p3`, effort `effort/xs..xl`, domain
`domain/{auth,agent-graph,ui,infra,docs,ops}`, type
`type/{bug,feature,refactor,architecture,docs,chore}`, routes
`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human` (`wontfix` uses
GitHub's close reason + comment).

If labels are missing, output the `gh label create` commands but do not run them — label
scheme is repo-level config. If `gh` is unavailable, output proposals as a markdown table
and tell the user how to apply manually.

**Every comment or issue posted during triage opens with:**

```
> *This was generated by AI during triage.*
```

On routing an issue with `--apply`, remove `needs-triage` (it is the entry state; a routed
issue no longer carries it).

## Composition

- Follows `/roadmap` (directional priority → per-issue order) and `/orchestrate --emit`
  (which labels its issues `needs-triage` — this skill is what clears them).
- `ready-for-agent` output feeds the day-run rail: the stated `check:` becomes the
  roadmap slice's `check:` field.
- Verification hands off to `/investigate` when a bug won't reproduce in minutes and the
  user wants the root cause now.
- Pairs with `/plan-feature` (p0/p1 → spec) and `/sweep` (stale-item closure).
- Grilling an underspecified request into shape mid-triage: `/grill-with-docs`, updating
  `CONTEXT.md`/ADRs as decisions land.
