# Default-branch PR gates — 2026-10-09

The operator requires a PR for default-branch updates in every active ojfbot repository, including administrators and automation, with no standing bypass. Active means non-archived, non-fork, with a default branch. Discovery found 51 active repositories: 24 public and 27 private. The operator explicitly left private enforcement pending after GitHub rejected private-repository ruleset access under the current plan.

## Server policy

Require pull requests, prohibit default-branch deletion and force pushes, and set no bypass actors. Match `~DEFAULT_BRANCH` so a default-branch rename retains coverage. Existing complete gates remain untouched. New gates layer with existing rules. Repair of the tool's named policy preserves its existing review requirements and other rules, activates it, removes bypass actors and adds missing baseline rules. Unexpected branch targeting requires manual reconciliation; the tool refuses to broaden its scope.

This baseline requires the PR process; it does not add a human approval count or invent a common CI check across different repositories. Repository-specific required checks remain in force. A separate daily-logger slice must remove CI-skip markers from generated PR commits before making its existing tests and secret scan mandatory.

GitHub administrators can still edit repository settings. An empty bypass list prevents bypass during normal updates; it does not remove administration privileges. Credential separation and independent approval enforcement remain separate decisions.

## Audit and apply

Use the logged-in `gh` identity. Audit is the default and exits nonzero for missing protection, platform blocks or errors. Apply is explicit, sequential, verifies effective server rules after every write, and skips already protected repositories. Re-running apply is idempotent. Reports may include private names; keep full-fleet reports local. Commit only public-repository receipts.

```sh
pnpm exec node scripts/enforce-pr-gates.mjs --public-only --output=/tmp/pr-gates-audit.json
pnpm exec node scripts/enforce-pr-gates.mjs --apply --public-only --repo=morning-cockpit --output=/tmp/pr-gates-pilot.json
pnpm exec node scripts/enforce-pr-gates.mjs --apply --public-only --output=/tmp/pr-gates-rollout.json
pnpm exec node scripts/enforce-pr-gates.mjs --public-only --output=/tmp/pr-gates-readback.json
```

New repositories require a fresh audit/apply. This slice provides a repeatable tool, not a scheduled drift monitor. Archived repositories and forks are excluded. `ojfbot` is a user account, so the rollout uses repository rulesets rather than organization rules.
